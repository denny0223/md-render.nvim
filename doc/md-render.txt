==============================================================================
INTRODUCTION						*md-render-introduction*

md-render.nvim is a Markdown rendering engine for Neovim.  It transforms raw
Markdown into richly highlighted, interactive content right inside your
editor.  Supports floating windows, tab views, in-place toggle between
source and render mode (|:MdRender-toggle|), and a pager mode for `less`-like
usage from the command line.

For writing, keep the source beside a live preview with synchronized
scrolling using |:MdRender-split|.

Features: ~

- Rich inline formatting (bold, strikethrough, inline code, links,
  Obsidian`==highlight==`)
- Tables with box-drawing borders, column alignment, and proportional sizing
- Callouts and folds (GitHub / Obsidian alert types with colored borders,
  icons, and folding you can toggle by click or `za` / `<CR>`)
- Code blocks with treesitter syntax highlighting; expandable when truncated
  (click or `za` / `<CR>`)
- Images (PNG, JPEG, WebP, GIF, animated GIF) displayed inline via terminal
  graphics protocol
- Video (MP4, WebM, MOV, AVI, MKV, M4V) played as animated frames inline
- Mermaid diagrams rendered as images inline
- PlantUML diagrams rendered as images inline, by a local renderer or by a
  server you name
- CommonMark paragraphs (soft-wrapped source lines are joined into one
  paragraph, including a list item's continuation lines and a blockquote
  body; no extra space is inserted between CJK characters)
- CJK spacing around inline markers (the spaces in `これは **強調** です。`,
  written only so that lenient parsers notice the `**`, are closed up; they
  stay when a neighbour is narrow, as in `これは **API** です。`)
- Nested block structure (a blockquote, callout, or fenced code block
  indented to a list item's content is rendered in place, not as literal
  text)
- CJK-aware word wrapping (JIS X 4051 kinsoku shori + optional BudouX phrase
  segmentation)
- Clickable links (mouse click to open URLs; mouse hover peeks the full URL
  in a subtle floating window; OSC 8 hyperlink support)
- `<details>` support (collapsible sections; toggle by click or `za` / `<CR>`)
- Library API for programmatic use from other plugins

==============================================================================
REQUIREMENTS						*md-render-requirements*

- Neovim >= 0.12 (uses |nvim_ui_send()| for terminal writes)
- For inline images and video with the default native backend ("kitty"),
  a terminal that supports the Kitty graphics protocol:
  - WezTerm (https://wezfurlong.org/wezterm/)
  - Kitty (https://sw.kovidgoyal.net/kitty/)
  - Ghostty (https://ghostty.org/)
- The optional Snacks backend also requires Unicode placeholders. Its
  documented setup targets Kitty, directly or inside tmux.
  See |md-render-snacks-image| for its dependencies and configuration.

==============================================================================
INSTALLATION						*md-render-installation*

The basic example uses the default native backend ("kitty"). For Kitty/tmux
images, viewport fitting, and zoom/pan, see |md-render-snacks-image| below.
Use this fork's default branch: inherited upstream release tags do not
include those features. The examples use version = false for this reason.

Using lazy.nvim: >lua

  {
    "denny0223/md-render.nvim",
    version = false,
    cmd = "MdRender",
    dependencies = {
      { "nvim-tree/nvim-web-devicons", version = "*" },
      { "delphinus/budoux.lua", version = "*" },
    },
    keys = {
      {
        "<leader>ms",
        "<cmd>botright vert MdRender split<CR>",
        desc = "Open Markdown preview on the right",
      },
      {
        "<leader>mp",
        "<Plug>(md-render-preview)",
        desc = "Markdown preview (toggle)",
      },
      {
        "<leader>mt",
        "<Plug>(md-render-preview-tab)",
        desc = "Markdown preview in tab (toggle)",
      },
      {
        "<leader>md",
        "<Plug>(md-render-demo)",
        desc = "Markdown render demo",
      },
    },
  }
<

                                                        *md-render-snacks-image*
Optional Snacks image backend ~

For static images, diagrams, viewport fitting, and image tabs, install:

- snacks.nvim, loaded and configured before opening an md-render preview.
- Kitty with Unicode placeholders. Inside tmux, add
  `set -g allow-passthrough on` to your tmux configuration and reload it.
  Other Snacks terminals have not been verified with this integration;
  the native backend's terminal list does not establish compatibility.
- ImageMagick with `magick` on Neovim's PATH for the complete image workflow.
  Image tabs require this command even for PNG; ffmpeg, sips, or an
  installation providing only convert cannot replace it.
- For Mermaid, mmdc (or the npx fallback) and its headless browser. Snacks
  displays images; it does not replace the diagram renderer. No browser
  window is opened. The npx fallback requires Node.js/npm and may download
  the CLI. See |md-render-dependencies| for other optional features.

Plugin managers install Neovim plugins; install command-line tools separately.
For lazy.nvim, replace the basic md-render spec above with this one, retaining
the optional icon/BudouX dependencies if you use them: >lua

  {
    "denny0223/md-render.nvim",
    version = false,
    cmd = "MdRender",
    dependencies = {
      {
        "folke/snacks.nvim",
        lazy = false,
        priority = 1000,
        opts = {
          image = {
            enabled = true,
            doc = { enabled = false },
            math = { enabled = false },
          },
        },
      },
    },
    config = function()
      require("md-render.image").setup({ backend = "snacks" })
    end,
    keys = {
      { "<leader>ms", "<cmd>botright vert MdRender split<CR>" },
      { "<leader>mp", "<Plug>(md-render-preview)" },
      { "<leader>mt", "<Plug>(md-render-preview-tab)" },
      { "<leader>md", "<Plug>(md-render-demo)" },
    },
  }
<
For vim.pack, add "https://github.com/folke/snacks.nvim" to vim.pack.add().
For mini.deps, add "folke/snacks.nvim" to md-render's depends list.
After both plugins have loaded, configure them in this order: >lua

  require("snacks").setup({
    image = {
      enabled = true,
      doc = { enabled = false },
      math = { enabled = false },
    },
  })
  require("md-render.image").setup({ backend = "snacks" })
<
If Snacks is already configured, merge these image options into its existing
configuration; do not call setup() twice. Disabling Snacks' document and math
rendering lets md-render own the preview; neither is needed by this
integration.

After loading the plugins, run :checkhealth snacks and check: >vim

  :echo executable('magick')
  :lua print(require("md-render.image").config().backend)
<
Expect 1 and "snacks", respectively. Inside tmux,
`tmux show-options -gv allow-passthrough` should print "on". Finally, open
a Markdown file containing a local PNG in Kitty and run :MdRender tab. Wait
for the image, place the cursor on it or its title, and press Enter to verify
that its image tab opens. Tool availability alone does not verify display.

The default backend remains "kitty". Both backends play animated GIFs and
videos; Snacks uses Kitty animation support, including inside tmux. Video
frame extraction requires ffmpeg. Snacks prepares all document images,
including off-screen images. Diagram rendering, downloads, and frame
extraction share two concurrent jobs across previews;
already running conversions may finish into the cache after closing.
Image-heavy documents therefore do more work up front.
See |md-render-image| for layout and |md-render-image-view| for navigation.

==============================================================================
MAPPINGS						    *md-render-mappings*

This plugin provides `<Plug>` mappings but does NOT set any default keybindings.
Map them yourself: >lua

  vim.keymap.set("n", "<leader>ms",
    "<cmd>botright vert MdRender split<CR>")
  vim.keymap.set("n", "<leader>mp", "<Plug>(md-render-preview)")
  vim.keymap.set("n", "<leader>mt", "<Plug>(md-render-preview-tab)")
  vim.keymap.set("n", "<leader>md", "<Plug>(md-render-demo)")
<

Use the <leader>ms example from the Markdown source window. Each invocation
opens a new preview on the right. See |:MdRender-split| for navigation.

						     *<Plug>(md-render-preview)*
<Plug>(md-render-preview) ~
	Toggle a floating preview window for the current Markdown buffer.  If
	the preview window is already open, it will be closed.

						 *<Plug>(md-render-preview-tab)*
<Plug>(md-render-preview-tab) ~
	Toggle a tab preview for the current Markdown buffer.  If the tab
	preview is already open, it will be closed.

						     *<Plug>(md-render-toggle)*
<Plug>(md-render-toggle) ~
	Toggle the current window between source and render mode for the
	current Markdown buffer.  No new window or tab is opened — the
	window's buffer is swapped in place.  See |:MdRender-toggle|.

							       *<Plug>(md-render-auto)*
<Plug>(md-render-auto) ~
	[EXPERIMENTAL] Toggle Insert-aware auto mode for the current buffer:
	render outside Insert mode, source while editing.  See
	|:MdRender-auto|.

							    *<Plug>(md-render-split)*
<Plug>(md-render-split) ~
	Open a horizontal split showing the source and rendered views of the
	current Markdown buffer.  See |:MdRender-split|.

							*<Plug>(md-render-demo)*
<Plug>(md-render-demo) ~
	Show a demo window with all supported Markdown notations.

Inside the preview window, the following keys are available:

	`q` / `<Esc>` / `<C-c>`	Close the floating/tab preview window
	`za`		Toggle the callout fold / expandable region under the
			cursor (no-op when the cursor is not on one)
	`<CR>`		Open the image under the cursor (Snacks backend), or
			toggle the callout fold / expandable region
	`gf`		Follow a local file link; Markdown targets stay rendered
			(toggle, split, floating, and tab previews)
	`<LeftMouse>`	Click links, toggle folds, expand regions
	`<MouseMove>`	Hover a link to peek its full URL in a small floating
			window at the bottom of the editor.  Requires
			'mousemoveevent' (md-render enables it automatically
			whenever a preview window is open).

For a split preview, switch to its window and close it with `:q` or `<C-w>c`.

Inside a render-mode buffer opened with |:MdRender-toggle|, `q` / `<Esc>` /
`<C-c>` are NOT bound to close — call |:MdRender-toggle| again to return to
source mode.  `<LeftMouse>`, `za`, and `<CR>` still toggle folds and expand
regions; `<CR>` also opens images with the Snacks backend. `<LeftMouse>`
opens links, and `<MouseMove>` hover-peek also stays active.

`gf` uses the exact link destination, resolved relative to the source file,
independently of the working directory. Markdown targets keep the current
preview window. Other files open for editing in the original source window;
floating/tab previews close first. `Ctrl-O` returns to the preceding rendered
document with its reading position and folds. After editing another file,
the rendered return uses the source window. Outside links, native `gf` and
counts such as `2gf` retain their usual behavior.

Directories open in the original source window through the configured
directory browser (such as netrw), closing floating/tab previews. The browser
retains its own navigation and buffer lifecycle.

`Ctrl-O` and `Ctrl-I` remain native Neovim commands. Each window has its own
jumplist. After opening another file in the source editing window, only the
immediately preceding rendered document is guaranteed on return. Earlier
preview history is not merged into that window.

Supported destinations are relative paths, POSIX absolute paths, and local
`file:///` URLs, including encoded filenames, inline/reference links, and
optional titles. Missing or unreadable targets leave the preview unchanged.
Fragments do not yet select headings. Pager navigation and Windows/UNC paths
are outside this feature's initial scope.

==============================================================================
COMMANDS						    *md-render-commands*

The plugin exposes a single user command, |:MdRender|, with subcommands.
The legacy top-level commands (`:MdRenderTab`, `:MdRenderToggle`, etc.) are
still registered as deprecated aliases — see |md-render-deprecated-commands|.

								     *:MdRender*
:MdRender [{subcommand}] [{args}] ~

	Render the current Markdown buffer.  The {subcommand} selects the
	display mode:

	  float       - floating preview window (default; same as bare
	                |:MdRender|)
	  tab         - toggle preview in a new tab
	  pager       - pager mode (full-screen, `q` to quit Neovim)
	  toggle      - in-place source ↔ render swap in the current window
	  split       - split source + render side-by-side; honours
	                `:vert`, `:tab`, `:topleft`, `:botright`
	  auto        - [EXPERIMENTAL] auto-toggle around Insert mode;
	                takes a second arg `on` / `off` / `toggle`
	                (defaults to `toggle`)
	  textsize    - [EXPERIMENTAL] scale headings in Kitty (on by default);
	                takes `on` / `off` / `toggle` / `auto` / `image` / `native` / `status`
	                (defaults to `toggle`)
	  demo        - show a demo window with every supported notation

	Tab completion lists the subcommands for the first arg, and
	`on` / `off` / `toggle` after `auto` and `textsize`.
	`textsize` also completes `auto` / `image` / `native` / `status`.

	The per-subcommand sections below describe behaviour in detail.

							     *:MdRender-float*
:MdRender float ~
	Toggle a floating preview window for the current Markdown buffer.
	This is the default if no subcommand is given (bare |:MdRender|).

							       *:MdRender-tab*
:MdRender tab ~
	Toggle a tab preview for the current Markdown buffer.

							    *:MdRender-toggle*
:MdRender toggle ~
	Toggle the current window between source and render mode in place
	(no new window or tab).  Useful when working with splits — for
	example, edit code in one split while showing the rendered README in
	the other.

	Behavior:

	- The render buffer is read-only and reused across toggles (cached
	  per source buffer; one render buffer per source).
	- When the source buffer is shown in multiple windows, only the
	  invoking window swaps. Edits from other windows update the preview
	  automatically.
	- Cursor position round-trips: the source line nearest the cursor in
	  render mode becomes the cursor target when toggling back, and vice
	  versa.
	- 'number', 'relativenumber', and 'list' are turned off on
	  render-mode windows.  The originals are stashed on the window and
	  restored when toggling back to source.

							      *:MdRender-auto*
:MdRender auto [on|off|toggle] ~
	[EXPERIMENTAL] This feature is new and the UX may change.  Please
	report any issues or rough edges.

	Auto-toggle the current buffer between source and render based on
	Insert mode.  The state is per buffer and recorded in
	`b:md_render_auto`.

	- `:MdRender auto on` flips the current buffer to render mode
	  immediately, and registers `InsertEnter` / `InsertLeave` autocmds
	  that swap to source on entry and back to render on leave.
	- `:MdRender auto off` removes the autocmds and the buffer marker.
	  If the current window is showing the render view of this buffer,
	  it also swaps back to source so the buffer ends up in the same
	  state it had before `:MdRender auto on`.
	- `:MdRender auto toggle`, or `:MdRender auto` with no second arg,
	  toggles between on and off.  Calling it twice returns the buffer
	  to its original (auto-off, source displayed) state.

	The plugin does not register a |FileType| autocmd of its own.  To
	enable auto mode for every Markdown buffer, add one yourself: >vim

	  autocmd FileType markdown silent! MdRender auto on
<
	Behavior:

	- The render buffer is `nomodifiable`, so |InsertEnter| cannot fire
	  on it.  While auto mode is active, the keys `i` / `I` / `a` / `A`
	  / `o` / `O` are remapped on the render buffer to swap to source
	  first and then enter Insert at the corresponding position.
	- `<Esc>` returns to source's Normal mode; the |InsertLeave|
	  autocmd then debounces a swap back to render after 50 ms.
	- Rapid `i<Esc>i<Esc>` keystrokes coalesce into the final state.
	- Only the current window is swapped.  Other windows showing the
	  same source need a manual |:MdRender-toggle|.

	What works on the render buffer: ~

	  Read-only operations: motion (hjkl, gg, G, ...), search (/, ?),
	  yank (y), visual selection, marks, `za` / `<CR>` (toggle folds
	  and expand regions), and <LeftMouse> (folds, expand, link open).

	  `:w` and `:w!` are forwarded to the source buffer so you can
	  save without leaving render mode.  Different filenames (e.g.
	  `:w other.md`, `:saveas`) are not supported — switch to source
	  with |:MdRender-toggle| first.

	  The render buffer is named `<source-path> [render]` so it's
	  identifiable in your statusline and pickers.

	What does NOT work on the render buffer: ~

	  The render buffer is `nomodifiable`, so any mutating operation is
	  blocked or silently a no-op:

	  - Editing keys: c C s S r R d D x X p P J ~ >> <<
	  - Undo / redo (u / <C-r>) — the render buffer has no edit
	    history of its own
	  - Ex commands that mutate the buffer: :s, :!filter, gq
	  - Macros that contain editing keys

	  Run |:MdRender-toggle| (or, in auto mode, simply press `i` / `I`
	  / `a` / `A` / `o` / `O`) to swap to source first.

							     *:MdRender-split*
:MdRender split ~
	Open a split window so the source Markdown buffer and the rendered
	view are visible at the same time. To write with a preview on the
	right, run this from the Markdown source window: >vim

	  :botright vert MdRender split
<
	The preview opens at the far right of the current tab, even with
	existing splits. Focus stays in the source window; edits update the
	preview without saving. In Normal mode, <C-w>p (Ctrl-w then p)
	selects the previous window. Immediately after opening the split,
	this takes you to the preview. To close the preview, switch to its
	window and use `:q` or `<C-w>c`; plain `q` is not a close key in
	this mode.

	Other layouts follow the standard Vim split modifiers: >vim

	  :MdRender split          " horizontal split
	  :vert MdRender split     " vertical split
	  :tab MdRender split      " open the other view in a new tab
	  :topleft MdRender split  " place at the top
	  :botright MdRender split " place at the bottom
<
	Behavior is symmetric:

	- From a source window, the new split shows the render.
	- From a render window created by |:MdRender-toggle| or
	  |:MdRender-split|, the new split shows the source.

	Each invocation opens a new window.

	The render buffer is shared with the |:MdRender-toggle| session
	cache, so a subsequent |:MdRender-toggle| reuses the same render
	buffer and edits propagate via the same 150 ms debounced
	live-update path used by toggle.

	Cursor and scroll position are synchronized between source and
	render windows: moving the cursor or scrolling on either side
	moves the other to the corresponding content position.

	A cursor that already maps to its counterpart stays where it is.
	Several source lines can share one rendered line — a collapsed
	<details>, a table, a figure — and mapping that line back would
	otherwise pull the cursor to the first line of the block.  A view
	within a line of where the map points is likewise left alone, so
	the other side is not scrolled back over the line it just
	scrolled by itself.

	Closing the split window with `:q` or `<C-w>c` does NOT destroy
	the render buffer; it stays cached on the source for future
	toggles or splits.

	Limitation: inline images can only be bound to one window at a
	time. Calling |:MdRender-split| twice from the source yields two
	render windows, but only the most recent one displays inline images
	(the older render window still receives text-content live updates).

							     *:MdRender-pager*
:MdRender pager ~
	Pager mode.  Renders the current Markdown buffer in full-screen with
	no chrome.  Press `q` to quit Neovim.  Useful for browsing Markdown
	files like `less`: >bash

	  nvim +"MdRender pager" README.md
<
	Add a shell alias for convenience: >bash

	  alias mdless='nvim +"MdRender pager"'
	  mdless README.md
<

							  *:MdRender-textsize*
:MdRender textsize [on|off|toggle|auto|image|native|status] ~
	[EXPERIMENTAL] Draw headings larger than the base font size in Kitty.
	The default is `auto`: image -> native OSC 66 -> ordinary text.
	See |md-render-image-headings| for image requirements.

	With no argument this toggles. `on` retains the selected backend;
	`off` removes heading overlays. `native` skips image probes and
	dependencies; explicit `image` falls back only to ordinary text.
	Unsupported backends leave usable text without changing the policy.

	`status` reports the selected policy, effective backend and reason.
	`auto` and `image` retry cached failures. Source/render toggling
	retains the selected policy. Switching rebuilds visible previews,
	waiting for active selections, operators, command-line input and
	yank feedback before changing the underlying layout.

	Auto images require confirmed terminal PNG support, measured cell
	dimensions, termguicolors and a working renderer. Pending work leaves
	text visible. PNG replies time out after 1.5 seconds; layout work
	times out after 5 seconds. Environment failures are cached for this
	session without repeated subprocesses or automatic warnings. Fix the
	environment, then run `:MdRender textsize auto` to retry. Local glyph,
	style or link limitations leave only that heading as ordinary text.

Image headings (experimental)			*md-render-image-headings*

Use `:MdRender textsize image` before or during a normal preview. Requires
Python 3, PyGObject, Pycairo, and Pango/PangoCairo and Cairo introspection data.
Font and base pixel size can be configured with: >lua

	require("md-render.text_size").setup {
	  backend = "image",
	  image = { font = "Noto Sans Mono,Noto Sans Mono CJK TC", font_size = "auto", python = "python3" },
	}
<
The default "auto" calibrates the chosen font to the terminal cell size,
preserving six distinct ratios. A positive pixel size overrides calibration.
Pango measures wrapping; the same byte ranges define buffer text, styles and
link targets. Layout work is asynchronous and reused by live previews.

Hover keeps the image stable. Clicks resolve the visible glyph through the
existing link handler, including the lower image row. Dragging reveals text
and selects from the clicked character. Moving through the left heading margin
keeps the image; entering its text area reveals only that rendered segment.
Visual selection and user yank/highlight feedback reveal affected rows while
other headings keep their images. Images return when the feedback expires.
Only search-matching headings withdraw; the search pattern and highlighting
state are preserved. Inactive previews remain readable.
Reflow and backend switches retain the source passage and heading character.
Background reflow waits for selections, pending operators, command-line input
and yank feedback to finish.

Images use MdRenderH1..MdRenderH6 and the existing inline highlight groups,
with Normal/NormalFloat supplying base colors. Unset backgrounds remain
transparent; a window-scoped overlay hides the underlying glyphs without
changing buffer text or coordinates. Inline styles preserve Markdown order
below user highlights such as vim.hl.on_yank(). Custom reverse, nocombine,
blending, alternate underlines and window highlight overrides retain text,
as do missing glyphs, oversized fonts, unrepresentable text/link targets and
headings inside <details>. Colorscheme/terminal resize events refresh the layout. Use `:MdRender textsize image` after direct font/highlight
changes or to retry a failed renderer. `:MdRender textsize status` reports
the reason; explicit image mode also reports failures in `:messages`.

For terminal Shift-drag selection, return to the Markdown source. In an
in-place preview, use |:MdRender-toggle|; toggle again to resume the preview
with the same heading backend. Open internal anchors with an ordinary
mouse click; use gf on local file links. Terminal OSC 8 modifier-clicks
are not supported over images.

To select rendered text or use its OSC 8 links, `:MdRender textsize off` keeps
the preview open with ordinary headings. Use `:MdRender textsize on` to
restore the selected backend. The source buffer has no preview-generated
OSC 8 links.

Images require Neovim >= 0.12, confirmed PNG support and termguicolors;
native sizing requires Kitty >= 0.40. Tested on Linux with Kitty, directly
and through a loopback SSH PTY to Linux. Python, Pango/Cairo and fonts run on the Neovim host;
PNG bytes are streamed to the client, with no shared image files. Images are disabled on Windows and through tmux. Other OS
and client combinations remain unverified.
For assistive technology or tools needing text, use `textsize off` or the
source buffer. Screen-reader compatibility has not been tested. Missing
rendering dependencies retain ordinary text.

------------------------------------------------------------------------------
Scaled headings (experimental)				*md-render-text-size*

[EXPERIMENTAL] This is new and Kitty-only.  The UX may change or the feature
may be withdrawn.  Please report issues or rough edges.

Kitty 0.40 added the text sizing protocol (OSC 66), which draws a run of text
at a multiple of the base font size.  md-render uses it to give every heading
level its own size:

	#	2.00x
	##	1.75x
	###	1.50x
	####	1.40x
	#####	1.25x
	######	1.17x

Select with `:MdRender textsize native`; auto uses it when image requirements
fail. Search, selection and user highlights reveal ordinary text. Turn it
off for the session with `:MdRender textsize off`, or permanently with: >lua

	require("md-render.text_size").setup { enabled = false }
<
The ladder is fixed.  Kitty's `s=` multiplies the *cells* a run occupies and
not only the font, so every level stays at `s=2` — one extra rendered row,
never more — and the sizes below 2x come from the protocol's fractional scale
(`n=` / `d=`) together with a per-run width (`w=`).  The protocol caps `d` at
15 and `w` at 7, which is why the deepest level lands on 1.17x rather than on
something closer to plain size.

How it works: ~

The scaled text is written straight to the terminal with `nvim_ui_send`, the
same channel |md-render-image| uses for Kitty graphics.  Neovim knows nothing
about it, which drives most of the design:

- The plain-size heading stays in the buffer and the scaled text is painted
  over it.  Every terminal repaint therefore degrades to the normal heading
  rather than to a blank line, and `y` / `/` / `:w` see the real text.
- A scaled heading reserves one extra rendered line for the taller glyphs,
  the way an image placement reserves rows.
- Headings wrap at `1 / size` of the usual width so that every level scales
  rather than only the ones that happen to fit, each wrapped line getting its
  own two-row block.
- A fractionally scaled heading goes out as several runs rather than one.
  `n=` / `d=` shrink the font without shrinking the cells, so each run has to
  state the width it wants in `w=`, and `w` is capped at 7 cells.
- That width is a whole number of cells while the text in it is not, so `w`
  is rounded up — never to nearest.  Given less room than its text needs
  Kitty drops the overflowing characters, which is far worse than the cost
  of rounding up: a cell or so of slack at the right-hand end of the run.
  Runs are cut where that slack disappears, preferring a boundary that comes
  out exact and otherwise ending the run after a space, so the leftover
  paints as a slightly wider word gap rather than as a hole in a word.  Text
  of one uniform character width — plain ASCII, or plain CJK — always lands
  exactly and never needs either.
- An emoji goes out in a run of its own.  A run with `w=` set is a single
  multicell character to Kitty, and a multicell is shaped with one font, so
  an emoji sharing a run with ordinary text takes the whole run down with it:
  measured on Kitty 0.48, every cell of the run turns into a missing-glyph
  box when the emoji sits in the middle of it, and the rest of the text is
  dropped when the emoji comes first.  Alone in a run it renders correctly.
  The cost is the rounding its own run carries, which shows up as slightly
  wider gaps either side of the emoji, and a heading that no longer fits is
  left plain.  `#` is exempt: it scales with `s=` alone, so its run carries
  `w=0` and Kitty splits the text into cells and picks a font per cell.
- Every level reserves a two-row block while only `#` fills it, so the rest
  are centered in theirs (`v=2`) rather than sitting against the top edge,
  which is the protocol's default.  At `######`, 1.17x in a block twice as
  tall, the top edge left almost a whole row empty underneath the heading.
- The level icon is drawn at normal size, but as a run of its own rather than
  as the plain text underneath, so that it is centered in the same block and
  stays level with the heading it labels.  `n=1:d=2` against `s=2` cancels
  the cell scale exactly, which is what keeps it at normal size.
  Its own run is also what keeps it legible: Kitty gives a scaled run exactly
  `s` cells per source cell, and these Nerd Font glyphs report as one cell
  wide while being drawn wider, so sharing the heading's run would clip the
  icon (`󰉬` would render as a bare "H").  Alone, `w=1` gives it a two-cell
  block — the width the icon already occupies — and it fits.
- Repainting happens on scroll, resize and cursor movement, debounced.  While
  a scroll is in flight the delay is stretched so a held `<C-e>` costs one
  repaint instead of one per step.

Limitations: ~

- Kitty >= 0.40 only.  Support is detected by asking the terminal to identify
  itself (XTVERSION) and requires a positive answer; a silent or non-Kitty
  terminal disables the feature.  This is deliberately strict because some
  terminals swallow an OSC 66 sequence together with its payload text, which
  would delete the heading rather than fall back to unscaled text.  Anywhere
  else the feature costs nothing and headings render as they always did.
- Inline formatting inside a heading (inline code, links, `==highlight==`)
  loses its colors while scaled — the whole run is drawn in the heading
  highlight.
- A heading whose second row would fall outside the window stays plain until
  it is scrolled into view.
- A repaint by anything else (another plugin forcing a redraw, a message or
  popup overlapping the window, the terminal shifting cells for a mouse
  scroll) drops the heading back to plain size, and there is no way to stop
  that happening.  Recovery is on three signals, in order of how quickly they
  arrive: a scroll, resize, or window opening or closing repaints at once; any
  redraw at all is picked up from a decoration provider on the tick after it;
  and |SafeState| covers the rest, rate-limited, with a 500 ms timer behind it
  for a repaint that never settles.  md-render's own repaints are handled
  properly rather than waited out: inline images and scaled headings both draw
  outside Neovim's grid and are both destroyed by a full repaint, so whichever
  of the two repaints announces it and the other puts itself back at once.
                                                 *md-render-eventignore*
- A plugin that repaints inside 'eventignore' `= "all"` costs a frame that
  cannot be recovered any sooner.  Autocmds are how everything above learns
  that anything happened, and that setting silences all of them.  The
  decoration provider still fires — it is not an autocmd — so the heading
  comes back on the next tick, but it does go for that one frame.
  nvim-scrollview (https://github.com/dstein64/nvim-scrollview) is the known
  case: it opens a float the size of the whole editor, moves a dozen small
  ones and closes them again, about twenty times a second while the mouse
  moves, all of it inside 'eventignore' `= "all"`.  Measured over fifteen
  seconds, 308 calls to `nvim_open_win` produced one |WinNew|.
  To turn it off while a preview is on screen, match on |b:md_render| rather
  than pairing open and close events — a preview can be opened more than once
  and split by hand, and asking "is one open" needs no bookkeeping: >lua

    local off = false
    vim.api.nvim_create_autocmd({ "WinNew", "WinClosed", "BufWinEnter" }, {
      callback = vim.schedule_wrap(function()
        local want = false
        for _, w in ipairs(vim.api.nvim_list_wins()) do
          if vim.b[vim.api.nvim_win_get_buf(w)].md_render then
            want = true
            break
          end
        end
        if want ~= off then
          off = want
          vim.cmd(want and "ScrollViewDisable" or "ScrollViewEnable")
        end
      end),
    })
<
- Each layout change costs a full-screen repaint to clear the previous scaled
  run, so scrolling is more expensive than usual.  When the window also holds
  images the image redraw does that clearing, and the scaled text is written
  after it rather than repainting the screen a second time.
- |md-render-telescope| and |md-render-snacks| previews opt out.  They redraw
  on every cursor step, and a full-screen repaint per step is not something a
  picker can afford.

PlantUML diagrams					 *md-render-plantuml*

A fenced block tagged `plantuml` or `puml` is rendered as an image, the way a
`mermaid` fence is.  Rendering is done by a `plantuml` on the PATH, or by
`java -jar $PLANTUML_JAR` when that variable points at a readable jar.

With neither, the fence stays a code block.  PlantUML renders on a server by
design, and rendering on somebody else's means sending the diagram there, so
that is not a fallback the plugin picks on its own.  Name a server and it will
be used: >lua

	require("md-render.image").setup {
	  plantuml_server = "https://plantuml.example.com/plantuml",
	}
<
"https://www.plantuml.com/plantuml" is the public instance, if that is the one
you want.  Either way the diagram source is sent to it.

A named server also needs `curl`.  Renders are cached under
`stdpath("cache")/md-render/plantuml`, keyed by the diagram source, so a given
diagram is sent once.

					  *md-render-float-footer*
display_utils.build_footer_chunks({info}, {width}) ~
	Build the `{text, hl_group}` chunk list for a float's status footer.

	Status info goes on the border footer rather than a statusline
	because floating windows only draw a statusline when 'laststatus' is
	1 or 2.  With 'laststatus' = 3 — what lualine's `globalstatus`
	option sets — a float's window-local 'statusline' is used for the
	global bar at the bottom of the screen instead, so the info would
	not only be invisible, it would overwrite your statusline.  The
	footer is always drawn and costs no content row.

	The layout is `<name>  <line>/<total>  <bar>`.  The bar is ten cells
	wide and made of box-drawing pieces — `━` for the part scrolled
	past, `─` for the rest, `╾` for a half-filled cell.  The light half
	is the glyph the border itself is made of, so the unfilled part
	reads as a continuation of the border rather than as a widget.

	The line number is right-aligned to the width of {total} so the
	footer keeps a fixed width as you scroll.  When it doesn't fit
	{width}, the bar shrinks to a minimum of four cells, then segments
	are dropped from the right (bar, then position, then name).  Widths
	are measured in display cells, so CJK file names are handled
	correctly.

	Parameters: ~
	  {info}   (table) Segments to show:
		   - {name}   (string|nil) File name
		   - {line}   (integer|nil) Current line (clamped to {total})
		   - {total}  (integer|nil) Total lines
	  {width}  (integer) Inner width of the float

	Return: ~
	  (table[]) Chunk list; empty when nothing fits.

                                                        *md-render-image-view*
With the Snacks backend and ImageMagick (magick), press <Enter> on an image
or its title to open a focused image tab. Its keys are set automatically:

  Playback      <Space>; pause/resume GIFs and videos.
  Zoom          + / = / - (also keypad + / -).
  Pan           h/j/k/l or arrows; 1/8 of the visible width/height.
  Half screen   zH / zL (left/right), <C-d> / <C-u> (down/up).
  Page          <C-f> / <C-b> or <PageDown> / <PageUp> (down/up).
  Fine scroll   <C-e> / <C-y>; one screen row down/up.
  Edges         0 / ^ / <Home> and $ / <End> (left/right);
                gg / <C-Home> and G / <C-End> (top/bottom).
  Fit           f; fit the complete image and center it.
  Help          ?; open this reference.
  Back          q / <Esc>; close the image tab and return to the document.

GIF and video tabs require Kitty 0.31 or newer and start playing automatically.
Pausing holds the current frame;
zooming and panning preserve the playback state. Playback controls affect only
this tab, independently of the document preview. This uses the same silent
frame preview as inline playback: with ffmpeg, 5 fps, at most 400x400 pixels
and 300 frames (up to 60 seconds).

Counts repeat pan, half-screen, page, and fine-scroll steps, e.g. 3j or
2<PageDown>. Pages keep two screen rows of overlap where possible. Edge
jumps preserve zoom and the other axis. Keypad navigation keys also work.

With 'mouse' enabled, wheel up/down zooms in/out like +/-, without changing
focus. Hold the left mouse button and drag to move the image with the
pointer; release to stop. Trackpad vertical scroll events also zoom.

Zoom ranges from 1x to 16x the fitted overview. It enlarges existing pixels;
it does not regenerate the diagram.

EXAMPLE							     *md-render-example*

A complete example showing how to render Markdown and display it in a buffer:
>lua

  local md = require("md-render")

  -- Render a single line of markdown
  local text, highlights, links =
    md.Markdown.render("**bold** and [link](https://example.com)")

  -- Build full document content
  local ContentBuilder = md.ContentBuilder
  local b = ContentBuilder.new()
  b:render_document(lines, {
    max_width = 80,
    indent = "  ",
    repo_base_url = "https://github.com/user/repo",
    autolinks = {
      {
        key_prefix = "JIRA-",
        url_template =
          "https://jira.example.com/browse/JIRA-<num>",
      },
    },
  })
  local content = b:result()

  -- Apply to a buffer
  local buf = vim.api.nvim_create_buf(false, true)
  local ns = vim.api.nvim_create_namespace("my_ns")
  md.display_utils.apply_content_to_buffer(buf, ns, content)

  -- Display images (Kitty Graphics Protocol terminal required)
  -- Images are automatically cleaned up when the window is closed.
  local win = vim.api.nvim_get_current_win()
  md.display_utils.setup_images(win, content, ns)
<

BUFFER VARIABLES				 *md-render-buffer-variables*

						       *md-render-b-md-render*
							       *b:md_render*
b:md_render ~
	`true` on every buffer md-render renders into — the floating preview,
	the tab and split views, the pager, the buffer |:MdRender-toggle|
	swaps in, and |:MdRender-demo|.  Set nowhere else, so a configuration
	can recognise one without matching on a buffer name or a filetype,
	both of which other plugins and the user are free to change.

	Buffer-local rather than window-local deliberately.
	|:MdRender-toggle| keeps its window and swaps the buffer inside it, and
	splitting a preview by hand creates a window this plugin never sees;
	the mark has to travel with the buffer for either to be recognised.
	To ask whether a preview is on screen, walk the windows: >lua

	  local function preview_visible()
	    for _, w in ipairs(vim.api.nvim_list_wins()) do
	      if vim.b[vim.api.nvim_win_get_buf(w)].md_render then return true end
	    end
	    return false
	  end
<

OPTIONAL DEPENDENCIES					*md-render-dependencies*

These are optional for basic Markdown rendering, but required by the features
that use them. Install command-line tools separately on Neovim's PATH.

  snacks.nvim          Optional image backend, viewport fitting, and image
                       tabs. See |md-render-snacks-image| for setup.
                       https://github.com/folke/snacks.nvim

  nvim-web-devicons    File type icons in code block headers.
  (or |mini.icons|)    Falls back to a built-in icon table.
                       https://github.com/nvim-tree/nvim-web-devicons
                       https://github.com/echasnovski/mini.icons

  budoux.lua           CJK phrase-level line breaking (BudouX).  Falls back
                       to character-level splitting (kinsoku rules still
                       apply).  https://github.com/delphinus/budoux.lua

  Treesitter parsers   Syntax highlighting in code blocks.  Code blocks
                       render without highlighting if parsers are missing.

  curl                 Download web images and video.  Can be replaced
                       via |image.set_download_fn()|.

  FFmpeg               Native JPEG/WebP to PNG; GIF / video frame extraction
  (ffmpeg/ffprobe)     for both backends.  Falls back to ImageMagick for
                       images; video requires ffmpeg.

  ImageMagick          Required for Snacks conversion of non-PNG images.
  (magick)             Image tabs require magick even for PNG; ffmpeg, sips,
                       or convert alone cannot replace it.
                       Native static conversion tries sips, ffmpeg, magick;
                       both backends try ffmpeg, then magick for GIF frames.
                       Snacks static conversion uses ImageMagick.
                       https://github.com/folke/snacks.nvim/blob/main/docs/image.md

  Mermaid CLI          Render Mermaid diagrams as images.  Falls back to
  (mmdc)               `npx -y @mermaid-js/mermaid-cli` (requires Node.js/npm;
                       may download the CLI). Both backends still need its
                       headless browser.
                       https://github.com/mermaid-js/mermaid-cli

  PlantUML             Render PlantUML diagrams as images.  Falls back to a
  (plantuml, or java   server only when one is named; see |md-render-plantuml|.
  with $PLANTUML_JAR)  https://plantuml.com/
